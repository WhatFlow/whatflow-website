# Comparison screenshot plan

The current 106 comparisons use two cover images: 99 template-editor screenshots and seven COD-settings screenshots. This revision will replace that repetition with topic-specific app views and supporting in-body screenshot blocks, stored in Payload with descriptive alt text, source and captions.

Capture from WhatFlow Demo Store only. Show sample data and clearly identify inactive workflow configurations. Keep screenshots focused on the UI relevant to the article; do not imply an editor preview proves message delivery, recovered revenue or a customer result.

| App area | Comparisons supported | Capture needed |
|---|---|---|
| Team inbox | Helpdesks, shared inboxes, seat pricing, support handoffs | Conversation view and available order context; actual controls observed before describing them |
| Automations | Transactional messaging, order updates, app versus API | Shopify event selection and message settings |
| COD | Confirmation, cash on delivery, checkout processes | Confirmation settings and reply-to-tag workflow |
| Broadcasts | Campaigns, segmented communication, email/SMS comparisons | Draft campaign and recipient selection; keep inactive |
| Templates | API providers, personalization, template mapping | Editor and variable mapping, used where relevant rather than on every article |
| Storefront buttons | Free buttons, theme integration, live chat | Product/cart/mobile placement and theme controls |
| Plan allowances | Feature access, staffing, total cost | Actual plan/usage screen without payment details |
| Connection setup | The two WhatFlow apps and API infrastructure | Official API connection/status view without secrets |
| Shopify extensions | Native workflow and external-dashboard comparisons | Actual extension inside an order or customer context, using demo records |
| Shopify Flow | Workflow builders, integrations and custom automations | Existing real trigger/action and inactive workflow captures, paired with a relevant new app screen |
| Reporting | Operational measurement comparisons | Actual available reporting controls with sample/empty data clearly identified |
| Back-in-stock/reviews | Retention and post-purchase comparisons | Actual configuration screens where available |

The detailed existing-capture inventory, limitations and article-to-theme assignments are in `audit.json`.
