## Give each order event one clear message owner

Create a hypothetical event ledger for one order with payment, partial fulfillment and a later cancellation affecting the remaining item. List which email or WhatsApp message is intended at each stage and which application owns it. Inspect a case where an older notification is still scheduled when the order changes. WhatFlow’s Shopify messages can support the conversational route, while email can retain detailed order records. The acceptance question is whether each update remains truthful for the current event and whether a customer reply reaches an informed colleague. Count messages per order only after this mapping, because a split journey can create more sends than the original budget assumed.

Test paid, fulfilled, partially fulfilled and canceled orders where relevant. Check timing and the information shown to the buyer, then have another teammate answer a follow-up question.
