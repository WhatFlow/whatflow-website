## Key takeaways

- Test the complete order task across working surfaces.
- Distinguish a synchronized contact from current order context.
- Check access and data freshness before acting on a reply.

## Start with the customer’s job

A busy store operator should be able to act on an order without reconstructing it in another system. A native-feeling Shopify workflow is valuable because the person answering a buyer is often also checking fulfillment, stock or payment. The integration needs to help that person complete the task, not merely copy a phone number into a contact list.

## Where each approach helps

An external dashboard can be useful when several stores or departments share a centralized operation. The tradeoff is the handoff back to Shopify. Check the working surfaces, permissions and data freshness instead of judging integration depth by the presence of a connector logo.

## Trace a changed address across the working surfaces

Hypothetical example: a buyer asks about delivery after an address has changed in Shopify. Ask the operator to find the intended order, identify the current address and explain the next step without relying on an old copied summary. Record which screen supplies the authoritative value and how the other surface updates or flags the difference.

Repeat with a cancelled order so a convenient message action cannot hide stale eligibility. Count the lookups and unresolved decisions as process observations, not a promised time saving. A Shopify-focused app may reduce context switching; a centralized dashboard may offer broader coordination. Choose based on the case the actual team can complete accurately.
