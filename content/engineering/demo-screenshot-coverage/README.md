The November 8, 2026 screenshot refresh uses real WhatFlow Demo Store captures from the Safwan Chrome profile. Captures were saved through Chrome's screenshot command, inspected, and resized and encoded as WebP for Payload Media. No customer messages were sent, workflows enabled, or app settings changed.

- [Capture manifest](capture-manifest.json): 30 approved images from Business API (18), Team Inbox (10), and Shopify Flow (2), with captions, alt text, dimensions, and file hashes. Incomplete loads, connection screens with numbers, and views exposing private data are excluded. The Shopify Flow Judge.me integration is an uninstalled template preview. The inbox assignment view shows the empty Mine queue.
- [Screen inventory](screen-inventory.json): records which candidate app screens have approved captures. Some Business API and Inbox views remain uncaptured or have no approved image. Chat Automation (linked-device) was not verified in this capture pass; Business API screenshots are not represented as Chat Automation screens.
- [Article inventory](article-inventory.csv): baseline for all 125 published blogs and 144 comparisons. The [placement plan](placement-plan.json) records each updated article, the specific section and image, and the articles left unchanged. There are 75 blog and 111 comparison updates. Captures are placed near matching workflow text; generic repetitive blocks are removed, and purpose-built supporting images and covers are retained.
- [Screenshot baseline](screenshot-baseline.json): the comparisons previously used 15 distinct screenshot URLs, with the same template-editor image repeated 78 times. After the update there are 35 distinct URLs in comparisons and that editor image appears 19 times. Blogs also use 35 distinct URLs, up from 19. All 144 comparisons now have a body screenshot.
- [Database rehearsal](rehearsal.json): compared all edited rows with the scoped production export and verified that only the article body screenshot blocks and update timestamps change, that every comparison retains its earlier revisions, and that replay is idempotent. All 186 edited bodies rendered through the site's RichText component.

Reproduction: provide fresh live `posts.json` and `comparisons.json` inventories in `SCREENSHOT_REFRESH_WORK` and run `scripts/prepare-demo-screenshot-refresh.mjs`. The existing `scripts/build-comparison-enhancement-sql.mjs` builds the comparison revisions. The rehearsal expects `before.sql` and the combined media, post and comparison SQL as `publish.sql` in that work directory.

[Live verification](live-verification.json) checks all 269 published CMS documents against their expected state, all 30 media hashes, and 39 representative rendered article pages. Three final editorial placement corrections (quick-reply button triggers, metrics, and conversation ownership) were separately verified against the live API and rendered pages.
